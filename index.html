What it is

A runtime for work that must survive.

Agent Elmer is the engine underneath durable, parallel agents. Work is committed before it is shown, fan-out is bounded by policy, and every result carries an address you can replay and verify.

Durable

Close the laptop. The work stays.

Every model call, tool call, queued input, checkpoint, and piece of application state is committed before it is displayed. A killed process resumes from its last checkpoint.

Parallel

Fan out without losing the thread.

Bounded parallel delegation runs independent work tracks at once, then joins them deterministically. The cap is declared, not emergent.

Deterministic

Same inputs. Same bytes.

Components are identified by content address, not host or filename. Evidence such as PIDs, timings, and endpoints never enters addressed output.

The differentiator

Most agent stacks ask you to trust the transcript. We give you a floor.

The model is allowed to propose. It is never allowed to become authority. A check that cannot pass refuses — there is no partial success and no silent pass.

The usual agent stack

  • One process, one turn, one fragile transcript
  • Kill the process and the work is lost
  • Run one agent and the rest of the team waits
  • Ask what happened and you get prose, not evidence
  • The model's output becomes the record

Agent Elmer

  • Durable jobs that resume from a checkpoint
  • Bounded parallel work tracks with a deterministic join
  • Content-addressed results that replay byte-identically
  • Fail-closed gates and recorded evidence
  • The operator ratifies; the model only proposes
