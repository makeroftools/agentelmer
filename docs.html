Docs · start and verify

Trust the floor, not the demo.

Four commands tell you whether the environment, the composed system, the services, and the work tracks are what they claim to be. Run them from the repository roots. The site check verifies this website.

01 · Start

Three commands to a known state.

From the CBP repository root:

cbp doctor
cbp check system
cbp track list
CommandWhat it provesExpected
cbp doctorThe front door resolves its agent, track, project, and tool dispatchers.Exit 0; the dispatcher table is rendered.
cbp check systemThe composed system check runs: repo line, CBP selftests, durable-pi line, listening services.Exit 0; verify-system: OK.
cbp track listThe work tracks and their worktrees, branches, and states are visible.Exit 0; one row per track.

02 · Verify the services

Four green rows, one topology.

From the durable-pi repository root, in the operator environment:

just net services status

Expect the backend, hub, CBP device, and proactive daemon to report active. The command reads the operator's device environment; credentials are supplied by the environment and never printed by this site. The endpoints are loopback-only:

ServiceEndpointUnit
durable-pi backend127.0.0.1:4780dpi-backend

You can also ask the proactive daemon directly for its heartbeat status. A fresh heartbeat is the difference between "the unit is active" and "the loop is actually ticking".

03 · Work tracks

Inspect a bounded line of work.

A work track is a bounded line of development that depends on a sandbox. Inspect it without reconstructing a chat transcript:

cbp track status <id>
cbp track report <id>
cbp track logs <id>

The legacy lane commands forward through the same registry with a deprecation warning. Machine identifiers stay qualifier-first; the human grammar is verb → object → qualifier.

04 · The deterministic floor

Nothing lands below the floor.

The governance floor validates every record and the committed registry, runs the stage controller, and executes every Transformer, gate, and execution Component selftest. It is fail-closed.

bash scripts/governance.sh
python3 tools/run.py governance.check
python3 tools/run.py governance.selftest

A registered tool is invoked through the gateway. A raw invocation of a registered tool is refused by design. If the floor cannot pass, it refuses; there is no partial success.

05 · This website

A projection with its own check.

The site is static HTML, CSS, and JavaScript. No framework, no build step, no third-party fonts, no trackers. The check verifies internal links, fragments, forbidden strings, and deterministic hashes.

python3 scripts/check-site.py

Run it from the worktree root. It exits non-zero on a broken internal link, a missing anchor, an absolute home path, a secret-like string, a stub marker, or a non-local script or stylesheet. It prints a stable SHA-256 list for the site files.
