The running system

Not a demo of a loop. A loop you can operate.

Agent Elmer is running as a composed system: a proactive daemon, a bounded parallel delegation engine, work tracks in their own sandboxes, and remote devices that render the same actions over their transport.

Proactive daemon healthy Backend, hub, and device active Floor green on the current line

01 · Proactive loop

The system wakes up, decides, and fans out.

A schedule fires a trigger. A classifier gate decides whether the trigger is admissible. If it is, the engine runs a bounded parallel delegation and records the outcome. No operator prompt is required for the loop to advance — only for the gates the operator owns.

schedule → trigger/v1 → classifier.gate/v1 → bounded run → verification → feedback/v1
A

Trigger

The schedule declares when work is due. The trigger is a recorded input, not an ambient clock the control plane relies on.

B

Gate

A pinned local classifier decides tier-one admissibility. The gate is deterministic code; the model is a recorded, clamped residue.

C

Run and report

Admitted work runs through the delegation engine. Outcomes return as feedback with evidence, or the loop refuses.

Verified by the live operator environment: the proactive service is active and its heartbeat is fresh. The loop's actions are the admitted trigger/v1, classifier.gate/v1, and feedback/v1.

02 · Bounded parallel delegation

Parallel where it is safe. Bounded where it is not.

Independent work runs at once; the concurrency is a declared policy, not whatever the machine happens to allow. Results are joined deterministically, so the addressed outcome does not depend on completion order.

Fan out

N independent tracks

Each child receives a bounded contract: paths, verbs, budgets, and the evidence it must return.

Join

One addressed result

The scheduler contract is that a parallel result and a sequential result are the same addressed artifact when the inputs are the same. This is the L3 requirement, not an extra claim.

Survive

Restart, resume, report once

Durable jobs resume from a checkpoint after a kill. Delivery is at-least-once with dedupe; the product promise is exactly-once reporting and effect.

Scope of the claim. Restart recovery for durable jobs is proven by re-run tests. A three-worktree, kill/restart/join transcript is not yet published, so it is not presented here as traction. See the evidence register.

03 · Work tracks

A unit of work that is not a chat thread.

A work track is a bounded line of development. It depends on a sandbox whose declared kind and capabilities satisfy its needs. The track construction is the durable record — source, build, child refs, database, and evidence — and it outlives the sandbox.

1

Launch

Create the track, its sandbox, and its declared capabilities.

2

Run

Agents and tools execute inside the sandbox. Every run is recorded.

3

Inspect

Status and evidence are readable without reconstructing the transcript.

4

Join

The coordinator merges a ready track. Tracks never merge themselves.

cbp track list
cbp track status <id>

The CLI is a projection of the same actions. Machine identifiers stay qualifier-first; the human grammar is verb → object → qualifier.

04 · Device and collaboration

The same action, from another device.

A remote device is an endpoint, not a second vocabulary. It registers, declares capabilities, and renders the same action triple over its transport. Offline, queue, and replay are projection concerns — they never create new actions.

Pair

Capabilities, not trust

A device declares what it can do. The operator gate remains sovereign over what it may do.

Collaborate

Participants and handoff

Presence, shared tracks, approvals, and handoff are projections of the same actors and actions.

Replay

Offline is not a new verb

A queued action replays through the same contract when the device returns. The semantic action does not fork.

05 · Interfaces

One registry. Every surface generated from it.

The projection registry is an index, not a store. It declares how each admitted action is exposed to the CLI, API, MCP, web, log/trace, TUI, docs, notification, embedded, and collaboration surfaces. A hand-written command that bypasses the registry is a defect.

06 · Boundaries

What is proven, and what is not claimed.

Proven or running

  • The governance floor passes on the current line.
  • cbp check system reports the composed system as OK.
  • The proactive daemon is active with a fresh heartbeat.
  • Durable job restart recovery passes its re-run tests.
  • Content addressing and evidence-free addressed output are enforced by the contracts.

Not claimed

  • No revenue, customers, market size, or unit economics.
  • No three-worktree kill/restart/join transcript as traction.
  • No pricing commitment: packaging is a draft.
  • No claim that the model is absent. The model is clamped.
